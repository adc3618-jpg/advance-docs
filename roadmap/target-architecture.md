# 목표 아키텍처

> 대상: 프론트 / 스크래핑 서비스 / 잡서비스(API). **백오피스는 이번 현대화 대상이 아니다.**

## 현재 아키텍처 요약

- 프론트: JSP + Java 1.8 모놀리식. 화면 렌더링과 서버 로직이 한 애플리케이션에 결합.
- 스크래핑 서비스 / 잡서비스(API): 별도 서비스로 분리되어 있으나 Java 1.8 기반, 상시 기동 구조.
- 데이터베이스 등 핵심 자원은 폐쇄망 내부에 위치, 클라우드 서비스에서 직접 접근 불가.
- 배포 파이프라인 부재로 수동 배포에 의존, 배포 주기가 김.

## 목표 아키텍처

- **프론트**: React 기반 SPA, AWS 클라우드에서 정적 호스팅/서빙. 화면은 BFF(Backend for Frontend)를 통해 API를 조합해서 사용.
- **API 계층**: 기존 JSP에 있던 서버 로직을 API로 추출해 재사용. 신규 기능은 API 우선으로 개발.
- **DMZ API**: 폐쇄망 내부 DB 접근이 필요한 요청은 DMZ에 위치한 전용 API를 통해서만 처리 — 클라우드에서 폐쇄망 DB로의 직접 연결을 만들지 않는다.
- **네트워크**: 가능한 구간은 AWS PrivateLink / Direct Connect / Transit Gateway 등 AWS Private Network로 구성해 인터넷 구간 노출을 최소화.
- **스크래핑 서비스**: 컨테이너화 후 Kubernetes Job/CronJob 기반 실행 — 상시 기동 대신 필요할 때만 자원을 사용하는 구조.
- **잡서비스(API)**: 배치 스케줄/이력 관리와 실행 자원(K8s)의 역할을 분리, API로도 노출해 다른 서비스가 재사용 가능하게 함.
- **CI/CD**: 신규 API 서비스부터 파이프라인을 구축하고, 프론트 클라우드 이관 시점에 프론트 파이프라인을 추가. 폐쇄망 연계 구간은 승인 게이트를 포함한 하이브리드 파이프라인으로 구성.
- **런타임**: Java 1.8 → 17(LTS) → 21(LTS) 단계적 업그레이드 (Spring Boot 사용 시 2.7 → 3.x 브릿지 경로 포함).
- (장기) **마이크로프론트엔드**: 프론트가 단일 서비스를 넘어 여러 마이크로서비스 화면이 모이는 슈퍼앱 구조로 확장.

## 변경점과 이유

| 변경 항목 | 현재 | 목표 | 이유 |
| --- | --- | --- | --- |
| 프론트엔드 기술 | JSP + Java 1.8 | React (SPA) | 화면/로직 결합 해소, 개발 생산성 및 배포 속도 개선 |
| 프론트엔드 호스팅 | 온프레미스 | AWS 클라우드 | 배포 자동화, 확장성 확보 |
| 서버 로직 재사용 | JSP 내부 로직 | API로 추출 | 프론트 전환 후에도 기존 로직 재활용, 타 서비스와 공유 가능 |
| 배포 프로세스 | 수동 배포 | CI/CD 파이프라인 | 배포 속도·안정성 개선, 빠른 배포 요구에 대응 |
| 폐쇄망 DB 접근 | (경로 미정/직접 접근 제약) | DMZ 전용 API | 클라우드-폐쇄망 간 안전한 단일 접근 통로 확보 |
| 폐쇄망 연결 방식 | - | AWS Private Network (PrivateLink 등, 가능한 경우) | 인터넷 구간 노출 없이 폐쇄망 극복 |
| 스크래핑 서비스 실행 방식 | 상시 기동 | K8s Job/CronJob 기반 | 실행한 만큼만 자원 사용, 비용 효율화 |
| 런타임 버전 | Java 1.8 | Java 17 → 21 (LTS) | 2026-11 Java 8 커뮤니티 지원 종료 대응, 성능/보안 개선 |
| 전환 방식 | - | Strangler Fig(점진적 전환) | 빅뱅 전환의 리스크(성능 저하, 프로젝트 좌초) 회피 |

## 마이그레이션 단계

1. **0단계 — 안전망 확보**: 특성화 테스트/골든 마스터 테스트로 현재 동작을 고정, 관측성(트레이싱·로깅·지연 지표) 구축, Java 업그레이드 로드맵 확정.
2. **1단계 — API 우선 확장**: 모놀리식 유지, 신규 기능은 API로 추가하고 기존 JSP는 vanilla JS로 API 연동. 신규 API부터 CI/CD 구축. 폐쇄망 DMZ API 개발 착수.
3. **2단계 — 클라우드 이관**: 도메인/인프라를 AWS로 이관, AWS Private Network로 폐쇄망 연결 구성. 프론트엔드 React 전환 및 클라우드 배포, 프론트 CI/CD 구축.
4. **3단계 — 백엔드 현대화 마무리**: 스크래핑 서비스·잡서비스 컨테이너화 및 Java 17/21 업그레이드 완료.
5. **4단계 — 구조 확장**: 프론트엔드 마이크로프론트엔드(슈퍼앱) 구조로 확장.
6. **5단계 — AI 결합**: 구축된 CI/CD·클라우드 인프라 위에서 AI 코딩·테스트·문서화 자동화 도입.
