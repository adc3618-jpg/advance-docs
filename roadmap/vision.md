# 비전

## 현재 상황

- 서비스 구성: 프론트 / 백오피스 / 스크래핑 서비스 / 잡서비스(API). 이번 현대화의 대상은 **프론트, 스크래핑 서비스, 잡서비스(API)** 3개이며 **백오피스는 대상이 아니다.**
- 프론트엔드는 JSP + Java 1.8 기반 레거시 모놀리식 구조 — 화면과 서버 로직이 강하게 결합되어 있음.
- 배포 과정이 불편하고 느려서, 빠른 배포가 필요한 상황에서도 대응이 어려움. CI/CD 부재가 근본 원인.
- 핵심 데이터베이스 등 자원이 폐쇄망 안에 있어 클라우드로의 이전이 단순하지 않음.
- Java 8은 2026년 11월 커뮤니티 무상 업데이트가 종료되어, 이후에는 보안 패치 공백이 생길 수 있음.

## 목표

- 레거시 모놀리식(JSP + Java 1.8)을 API + React 조합으로 전환하고, 프론트엔드를 클라우드 서비스로 이전한다.
- 기존 JSP 로직은 버리지 않고 API로 노출해 재활용한다.
- CI/CD 환경을 구축해 배포 속도와 안정성을 함께 개선한다.
- 폐쇄망 DB 접근을 위한 DMZ API를 구축하고, 가능하면 AWS Private Network(PrivateLink 등)로 인터넷 구간 노출 없이 폐쇄망을 극복한다.
- 스크래핑 서비스와 잡서비스(API)도 컨테이너화·Java 버전 업그레이드를 통해 함께 현대화한다.
- 위 전환은 한 번에 갈아엎는 빅뱅 방식이 아니라, Strangler Fig 패턴으로 점진적으로 진행한다 — 레거시와 신규가 공존하는 기간을 계획적으로 관리한다.
- (장기) CI/CD·클라우드 인프라가 갖춰진 뒤, AI를 코딩·테스트·문서화 자동화에 접목한다.

## 타임라인

| 시기 | 목표 |
| --- | --- |
| 0단계 (착수 전 준비) | 특성화 테스트/골든 마스터 테스트로 현재 동작 고정, 관측성(트레이싱·로깅·지연 지표) 확보, Java 버전 업그레이드 로드맵 확정 |

| 2단계 | 도메인/인프라 AWS 이관, AWS Private Network로 폐쇄망 연결, 프론트엔드 React 전환 및 클라우드 배포, 프론트 CI/CD 구축, 스크래핑·잡서비스 컨테이너화 |
